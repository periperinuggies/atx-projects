System Design
Technical Architecture
Seven-layer pipeline from raw source ingestion to interactive wiki UI. Designed to run continuously on the existing Raspberry Pi / VM infrastructure.
Layer 1

Ingestion

Scrapers per source type — PDF extraction, HTML parse, JSON feed, AustLII bulk download, Hugging Face dataset stream.

PythonBeautifulSouppdfplumberdatasetsaiohttp
Layer 2

Normalisation

Standardise case citation format, extract metadata (court, date, judge, case number, parties), deduplicate across sources.

regexspaCypydantic
Layer 3

NLP Extraction

Named entity recognition (people, organisations, locations, legislation). Part-of-speech tagging for noun/verb/concept extraction. Legal term glossary linking.

spaCyGemini Flashen_core_web_trf
Layer 4

Storage

SQLite or Postgres for structured metadata. Full-text search via FTS5 or Meilisearch. Vector embeddings (Gemini) for semantic search. Citation graph in a graph structure (networkx or SQLite adjacency).

SQLite FTS5MeilisearchGemini embeddings
Layer 5

Link Graph

Every noun, named entity, legislation reference, and case citation becomes a node. Every document is an edge. Click any term → see every document it appears in across all courts.

networkxLawCiteSQLite
Layer 6

Scheduling

Cron jobs via OpenClaw for continuous ingestion. Federal Court lists scraped daily at 8am. AustLII judgments polled hourly. WA court PDFs checked weekly.

OpenClaw cronGemini FlashRaspberry Pi
Layer 7

Wiki UI

Static-generated or Streamlit wiki. Every page is a term, entity, court, or judge. Interlinked. Filterable by jurisdiction, date, charge type, outcome. Full-text and semantic search.

StreamlitOR Next.jsMeilisearch
Knowledge Graph
The Interlinking Layer
Every document is decomposed into its constituent parts of speech and entities. Each becomes a clickable node linking to every other document it appears in.

Named Entities (NER)

People, organisations, locations, legislation — automatically extracted and indexed. Click a person's name to see every case they appear in, across every court.

Andrew Larsen Corruption and Crime Commission Perth Crimes Act 1914 Australian Federal Police Wesfarmers Ltd

Legal Concepts (Nouns)

Core legal nouns extracted and linked. Search for "conspiracy" and see every case where that concept features — across all courts and all time.

conspiracy negligence res judicata mens rea estoppel habeas corpus injunction damages

Actions & Outcomes (Verbs)

Judicial actions and rulings extracted and indexed. Filter all cases where a court "quashed", "dismissed", "upheld" — see patterns in outcomes across jurisdictions.

convicted acquitted dismissed remanded sentenced quashed upheld referred

Citation Network

Built on LawCite's cross-jurisdiction citation data. Every case cites others; every statute is cited by cases. The full citation graph is the backbone of the wiki's inter-document links.

  • Forward citations: cases citing a given decision
  • Backward citations: what a case relied upon
  • Legislation ↔ case bidirectional links
  • Judge → all decisions made by that judge
  • Counsel → all matters they appeared in
Execution Plan
Roadmap
Four phases from backfill to live wiki. Designed to run on existing infrastructure — VM + Raspberry Pi + GitHub Pages.
Phase 1
Foundation
Weeks 1–3
Download Open Australian Legal Corpus from Hugging Face — 229K documents, instant historical backfill
Parse and normalise into unified schema: case_id, court, date, jurisdiction, parties, full_text, url
Load into SQLite with FTS5 full-text search index
Build AustLII scraper for daily incremental updates (new judgments since last run)
Deploy scraper cron job via OpenClaw on Raspberry Pi
Phase 2
NLP + Graph
Weeks 4–7
Run spaCy NER over full corpus — extract persons, orgs, locations, legislation, monetary amounts
Build entity index table linking every entity to every document it appears in
Parse LawCite citation data to build case-to-case citation graph
Add Gemini Flash embeddings for semantic search (most similar cases)
Extract legal concept nouns and outcome verbs for the clickable tag layer
Phase 3
Live Sources
Weeks 8–12
Add per-court scrapers for daily lists: WA District Court, Federal Court (all registries), NSW Caselaw
PDF ingestion pipeline for WA Supreme Court case inventory and similar court-specific PDFs
QLD, VIC, SA, NT, ACT, TAS court scrapers (judgment feeds + daily lists where available)
Deduplication layer to reconcile same judgment from multiple sources (AustLII + court direct)
Phase 4
Wiki UI
Weeks 12–16
Streamlit wiki UI with sidebar filters: jurisdiction, court level, date range, charge type, outcome
Entity pages: every person, org, legislation, and legal concept gets its own page with all linked documents
Case pages: full text, extracted entities, citations in/out, judge, parties, outcome chip
Map view: cases plotted by court location (Leaflet), filterable by date and type
Full-text + semantic search bar powered by Meilisearch + Gemini embeddings
Deploy to larsenfamily.com.au subdomain via Cloudflare tunnel

Legal & Ethical
Scraping & Use Considerations
Australian court data is generally public record, but some constraints apply.

✓ Generally permitted

AustLII explicitly allows scraping for non-commercial research with attribution. Federal Court, High Court, and FCFCOA publish judgments for public access. Court lists are public record.

⚠ Rate limiting required

All scrapers must respect robots.txt and implement polite delays (1–2s between requests). AustLII in particular requests considerate access. Identify your scraper with a User-Agent.

⚠ Suppression orders

Some matters have suppression or non-publication orders over names or details. Scrapers should not display suppressed content. AustLII and court sites typically redact these already.

⚠ Privacy considerations

Victim names, juvenile defendants, and family law matters may be protected. Store and display only what courts have already made public. Do not cross-reference with commercial identity databases.
